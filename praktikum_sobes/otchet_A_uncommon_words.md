## 1. Условие (4:40–6:00)

Интервьюер даёт две строки, состоящие из слов. Слово считается необычным, если в одной строке оно встречается ровно один раз, а в другой не встречается вообще. Нужно вернуть список всех таких слов. Это задача LeetCode 884.

**⏸ Пауза на 5:40. Какие два вопроса по условию я бы задал перед написанием кода:**

**Совпало ли с ответом в видео:** сверить после продолжения просмотра: **совпало / не совпало**. Важна не конкретная формулировка, а то, что нужно заранее уточнять граничные случаи.

**Какой вопрос по условию кандидат задала сама:** кандидат пересказала задачу своими словами и уточнила, правильно ли поняла условие.

## 2. Идея решения (6:00–12:40)

**⏸ Пауза на 6:00. Моё решение приёмом из модуля 18 и его сложность:**

Я бы объединил слова из обеих строк, затем с помощью словаря-счётчика `dict` подсчитал, сколько раз встречается каждое слово. После этого выбрал бы слова со значением счётчика `1`. Например, для строк `"this apple is sweet"` и `"this apple is sour"` результат — `sweet` и `sour`. При `n` и `m` словах во входных строках время — **O(n + m)** в среднем, дополнительная память — **O(n + m)** в худшем случае.

**Сверка ответа на паузе:** **сверить по видео: совпало / не совпало**.

**Почему «один раз в одной строке и ни разу в другой» равносильно «ровно один раз в объединённой строке»:**

Если слово встретилось один раз в первой строке и ни разу во второй, его общая частота равна `1 + 0 = 1`. То же справедливо в обратном случае. Если общая частота равна единице, значит, слово встретилось ровно один раз только в одной из двух строк.

**Около 10:40. На что интервьюер наводит кандидата вопросом о подсчёте слов:**

На предварительное разделение строк **на отдельные слова** (например, через `split()`), чтобы затем можно было пройти по ним циклом и посчитать частоты. Моя первоначальная мысль была об объединении строк; для подсчёта дополнительно необходимо выделить слова. **Точную формулировку подсказки сверить по видео.**

## 4. Краевые случаи (21:00–23:00)

**Интервьюер просит назвать необычные входы. Кандидат назвала пустую строку. Ещё два случая:**

**Примечание:** это важные проверки для алгоритма; **нужно сверить по видео**, действительно ли кандидат назвала именно эти два случая.

**Около 22:00. Что возвращают два варианта `split`:**

Для строки `"  a b"` (два пробела в начале):

- `"  a b".split(" ")` → `["", "", "a", "b"]` — явный разделитель сохраняет пустые элементы между соседними разделителями и перед первым словом.
- `"  a b".split()` → `["a", "b"]` — разделение по пробельным символам пропускает пустые части.

**Что интервьюер ответила бы на вопрос о пустой строке заранее (около 24:00):**

## 6. Сложность (29:00–33:00)

**⏸ Пауза на 29:40. Время, память и что означает `n`:**

Пусть `n` — количество слов в первой строке, а `m` — количество слов во второй. По каждому слову проходим ограниченное число раз. Время — **O(n + m)** в среднем, а память для словаря частот и результата — **O(n + m)** в худшем случае. Если обозначить суммарное число слов через `N = n + m`, можно записать **O(N)** по времени и памяти.

**Сверка ответа на паузе:** **сверить по видео: совпало / не совпало**.

**Кандидат сказала «n — количество времени, затраченного на решение». Как её поправила интервьюер:**

`n` — это **размер входных данных**, а не время работы программы. Время работы описывают функцией от размера входа. **Точную реплику сверить по видео.**

**Кандидат назвала «2n». Какой ответ дала интервьюер и почему строки могут быть разной длины:**

В обозначении Big O постоянный множитель отбрасывают: `O(2n) = O(n)`. Но здесь две входные строки могут иметь разное число слов, поэтому точнее писать **O(n + m)**, где `n` и `m` — размеры соответствующих входов. Эта оценка также приводится в публичном описании видео.

**Почему два последовательных прохода не дают O(n²):**

Потому что циклы идут **друг за другом, а не вложены один в другой**. Их затраты складываются: `O(N) + O(N) = O(N)`.
