## 1. Задача 1 · Смена знаков (0:40–2:40)

Дан массив целых чисел. За одну операцию можно изменить знаки **двух** элементов. Требуется получить максимальную сумму.

**⏸ Пауза на 2:40. Сколько отрицательных чисел останется? Почему:**

Чётность числа отрицательных элементов не меняется при перевороте двух ненулевых чисел: при чётном количестве минусов можно сделать все числа неотрицательными, при нечётном хотя бы один минус останется. **При наличии нуля есть исключение:** смена знака нуля ничего не меняет, поэтому его можно использовать как «пару» для переворота одного отрицательного числа. **Сверка с видео:** на паузе записан свой ответ; точного подтверждения в доступных материалах нет.

**Уточнение кандидата (около 2:20):** кандидат спросил, можно ли менять знаки последовательно — например, сначала у −2 и 1, а затем у того же элемента с 3. Интервьюер ответил, что количество операций не ограничено. Этот момент я просмотрел самостоятельно.

## 2. Идея и сложность (2:40–4:40)

**⏸ Пауза на 2:40. Каким числам выгодно оставить минусы:**

Если число минусов нечётное и нуля нет, выгодно оставить отрицательным элемент с **наименьшим абсолютным значением**: это минимизирует потерю в общей сумме. Если минусов чётное число или есть ноль, можно получить сумму абсолютных значений всех элементов. **Сверка с видео:** на паузе записан свой ответ; точного подтверждения в доступных материалах нет.

**Идея кандидата:** подсчитать количество отрицательных чисел, взять модули, отсортировать и сделать отрицательными `k` наименьших по модулю элементов. Время — O(n log n) из-за сортировки. (Идея указана в бланке преподавателя.)

**Зачем кандидат уточнил, можно ли менять исходный массив (около 4:00):** чтобы понять, можно ли делать преобразования на месте и заявлять O(1) дополнительной памяти. Если нужно сохранить входной массив без изменений, потребуется копия.

**Память при копировании массива модулей:** O(n), а не O(1). Сама сортировка может также требовать дополнительную память — зависит от реализации.

## 3. Код и проверка (5:20–18:40)

**«У нас не языковая секция» (около 5:20):** важнее объяснить алгоритм, его корректность и сложность, чем помнить наизусть каждую особенность синтаксиса JavaScript. (Точная реплика требует проверки по видео.).

**Ошибка в 18-й строке кода (15:23):** кандидат написал `acc = item * x` вместо `acc += item * x`. При присваивании накопленная сумма на каждой итерации заменяется текущим слагаемым, а не увеличивается на него. Это видно по коду на записи.

**Ответ для `[4, -5, 8, -9]` по идее кандидата:** два отрицательных числа, поэтому можно сделать все значения положительными: `4 + 5 + 8 + 9 = 26`.

**Случай `[-5, -3, 0]`:** по описанной в бланке идее кандидата `k = 2`; после взятия модулей и сортировки получим `[0, 3, 5]`, затем ставим минус двум наименьшим: `[-0, -3, 5]`, сумма **2**. Однако можно просто перевернуть знаки обоих отрицательных чисел и получить `[5, 3, 0]`, сумму **8**. Поэтому идея «минус k самым маленьким» ошибочна при наличии нуля (а без нуля тоже не всегда оптимальна при чётном k). **Правильный максимум — 8.** (Этот пример предложен преподавателем для самостоятельного анализа; в видео его не проверяли.).

**Какой вопрос стоило задать про ноль:** «Может ли массив содержать 0 и можно ли выбирать ноль как один из двух элементов при смене знаков?»

## 4. Задача 2 · Вечеринка Пети (18:40–20:20)

У каждого друга есть достаток и счастье для Пети. Нужно выбрать гостей, чтобы ни у кого достаток не был в два или более раза меньше достатка другого гостя, и максимизировать сумму счастья.

**⏸ Пауза на 20:20. Подход:** отсортировать друзей по **достатку**, затем использовать **скользящее окно переменной длины** и поддерживать сумму счастья внутри окна. **Сверка с видео:** на паузе записан свой ответ; точного подтверждения в доступных материалах нет.

---

## 5. Путь к решению (20:20–24:40)

**Почему нельзя просто взять самых счастливых (около 20:40):** их достаток может сильно различаться, из-за чего часть гостей будет чувствовать себя некомфортно.

**Что даёт сортировка по достатку (около 22:00):** для выбранных друзей достаточно сравнить минимальный и максимальный достаток. При неотрицательном счастье допустимую группу выгодно рассматривать как непрерывный отрезок отсортированного списка: добавление промежуточных друзей не нарушает ограничение и не уменьшает сумму.

**Зачем интервьюер перефразировал решение (около 23:00):** проверил, что идея окна понятна обоим: расширяем правую границу, при нарушении условия двигаем левую. Это помогает согласовать инвариант до написания кода.

**Из чего складывается O(n log n):** сортировка — O(n log n); движение двух указателей и обновление суммы — O(n). Итого O(n log n). **Память O(1) зависит от способа сортировки** и учитывает только окно, не копию списка и не память сортировки.

## 6. Код (25:00–39:20)

**Что исправил кандидат после вопроса об уровне достатка и счастья (около 29:00):** в накопленную сумму следует добавлять **счастье**, а достаток использовать только при проверке ограничения окна. (Логика исправления следует из формулировки вопроса преподавателя.).

**Условие `2 * достаток[left] < достаток[right]` (30:20–31:00):** если достатки равны 1 и 2, гости **не могут** быть вместе: 1 в два раза меньше 2. Условие `2 * 1 < 2` ложно, поэтому окно ошибочно не сдвинется. Для ограничения «в два или более раза» нужно `2 * достаток[left] <= достаток[right]`.

**Проверка решения (36:40–39:20):** по просмотренным кадрам кандидат и интервьюер запускали следующие примеры:

| № | Вход (`maxHappiness`) | Результат на экране | Что проверяет |
|---|---|---:|---|
| 1 | `[[1, 3], [5, 2], [3, 2]]` | `4` | Небольшой набор с разным достатком |
| 2 | `[[1, 3], [5, 2], [3, 2], [1, 3], [1, 3]]` | `9` | Дополнительные друзья с одинаковым достатком |
| 3 | `[[1, 3], [5, 2], [3, 2], [1, 3], [1, 3], [3, 11]]` | `15` | Гость с высоким счастьем |
| 4 | `[[1, 3]]` | `3` | Один гость |
| 5 | `[]` | `0` | Пустой список |
| 6 | `[[1, 1], [1, 2], [1, 3], [1, 4]]` | `10` | Одинаковый достаток; дополнительный тест интервьюера |
| 7 | `[[1, 1], [1, 2], [12, 12], [1, 4]]` | `12` | Сильный разброс достатка; дополнительный тест интервьюера |

Сначала проверялись обычные наборы, затем крайние случаи (один и ноль гостей). Интервьюер дополнил проверку двумя примерами. **Важно:** здесь указаны именно показанные результаты запуска, а не утверждение, что алгоритм корректен на всех входах. В коде на записи видно условие с `<`, хотя граница «в два раза» требует `<=`.
