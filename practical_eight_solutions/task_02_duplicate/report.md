## 1. Условие задачи

Вернуть `True`, если хотя бы одно число встречается в списке дважды или более. В противном случае вернуть `False`.

**Пример:** `[4, 9, 2, 9] → True`.

## 2. Методика измерений

Для эксперимента использованы три набора данных:

- 1 000 случайных чисел;
- 100 000 различных чисел;
- 100 000 чисел с единственным повтором в конце.

Время измерялось через `time.perf_counter()`. Каждый алгоритм запускался пять раз, после чего вычислялась медиана.

Пиковая дополнительная память измерялась через `tracemalloc`.

Количество проверок определялось с помощью класса `CountedNumber`, учитывающего сравнения значений и вычисления хешей. Служебные условия циклов в этот показатель не входят.

Для ограничения длительности эксперимента использовался модуль `multiprocessing`.

Обозначение `TIMEOUT` означает превышение двухсекундного лимита ожидания отдельного процесса, включая накладные расходы его запуска.

## 3. Таблица вариантов

Время указано в миллисекундах, пиковая память — в КБ (1024 байта) для n = 100 000.

| Вариант / идея | Время n = 1 000 | Время n = 100 000 | Проверки 1 000 / 100 000 | Худшая сложность | Доп. память | Пик памяти, КБ | Сценарий 1 | Сценарий 2 |

## 6. Выбор решения для заказчиков

### Сценарий 1. Большой вход, память ограничена

**Условия:** n = 10 000 000, числа поступают по одному, объём памяти ограничен.

**Условно подходит — `set` с ранним выходом.**

Алгоритм позволяет обрабатывать числа последовательно и завершать работу сразу после обнаружения повтора.

Однако дополнительная память составляет O(n). Если все числа различны, множество может потребовать значительно больше доступной памяти.

Без ограничений на диапазон чисел и точного объёма доступной памяти ни один из восьми вариантов не гарантирует выполнение всех требований сценария.

Для гарантированного решения необходимо уточнить ограничения заказчика, например допустимость использования внешнего хранилища или ограниченность диапазона чисел.

### Сценарий 2. Малый вход, нужен быстрый ответ

**Условия:** n = 100, один запрос.

**Подходит — `dict` с ранним выходом.**

На малом экспериментальном наборе алгоритм показал наименьшее время — 0.0140 мс. Он прекращает выполнение сразу после обнаружения повторяющегося числа.

Выбор сделан на основе измерений при n = 1 000. Отдельные замеры для n = 100 не проводились, поэтому преимущество перед `set` не гарантируется.

## 7. Вывод

В ходе практической работы были реализованы и исследованы восемь способов обнаружения повторяющихся элементов.

На большом экспериментальном наборе наиболее быстрым оказался вариант `set()`.

На малом наборе лучший результат показал словарь с ранним выходом.

Алгоритм с двумя вложенными циклами не уложился в установленное ограничение времени на больших входных данных.

Бинарный поиск также оказался менее эффективным, поскольку вставка элемента в отсортированный список требует сдвига других элементов.

Эксперимент показал, что при выборе алгоритма необходимо учитывать не только временную сложность, но и расход памяти, расположение повторяющихся элементов и особенности поступления входных данных.
