**Ограничение времени:** 2 секунды  
**Ограничение памяти:** 256 МБ

## 1. Условие задачи

Вернуть длину самой длинной подряд идущей серии одинаковых чисел. Для пустого списка вернуть 0.

**Пример:** `[1, 1, 2, 2, 2, 3] → 3`.

## 2. Методика измерений

Для эксперимента использованы три набора данных:

- 1 000 случайных чисел;
- 100 000 случайных чисел;
- 100 000 чисел с длинной серией в конце.

Случайные числа генерировались в диапазоне от 0 до 100. Для воспроизводимости использовалось `random.seed(42)`.

В третьем наборе первые 90 000 элементов случайные, а последние 10 000 равны 101.

| Набор | Количество элементов | Максимальная серия |
|---|---:|---:|
| Малый | 1000 | 2 |
| Большой | 100000 | 3 |
| Серия в конце | 100000 | 10000 |

Время измерялось через `time.perf_counter()`. Каждый алгоритм запускался пять раз, после чего вычислялась медиана.

Пиковая дополнительная память измерялась через `tracemalloc`.

Количество сравнений определялось с помощью класса `CountedNumber`. Учитывались только сравнения элементов списка. Сравнения счётчиков и служебные условия циклов не учитывались.

Копирование входных данных выполнялось до начала замеров.

Обозначение `TIMEOUT` означает превышение двухсекундного лимита ожидания отдельного процесса, включая накладные расходы его запуска.

Время указано в миллисекундах, пиковая память — в КБ (1024 байта) для n = 100 000.

## 6. Выбор решения для заказчиков

### Сценарий 1. Большой вход, память ограничена

**Условия:** n = 10 000 000, дополнительная память не более 8 МБ.

**Подходит — один проход через итератор.**

Алгоритм последовательно перебирает элементы списка, сравнивая каждый элемент с предыдущим. Для поиска максимальной серии достаточно хранить предыдущий элемент, длину текущей серии и максимальную длину.

Временная сложность составляет O(n), дополнительная память — O(1).

При n = 100 000 время выполнения составило 4.2656 мс, а пиковая дополнительная память — 0.0469 КБ.

Алгоритм не создаёт дополнительных массивов и не использует рекурсию.

Другие варианты с постоянной дополнительной памятью также могут соответствовать ограничению памяти, но уступают итератору по результатам замеров.

Прямой эксперимент при n = 10 000 000 не проводился. Выбор основан на теоретической сложности и результатах экспериментов. Соблюдение двухсекундного ограничения на полном размере входа требует отдельной проверки.

### Сценарий 2. Малый вход, нужен быстрый ответ

**Условия:** n = 100, нужен быстрый ответ для одного списка.

**Подходит — один проход через итератор.**

На малом экспериментальном наборе время выполнения составило 0.0663 мс. Это лучший результат среди восьми вариантов.

Алгоритм не требует предварительной обработки данных, создания дополнительных массивов или рекурсивных вызовов.

Отдельные замеры при n = 100 не проводились. Выбор основан на результатах проведённых экспериментов.

## 7. Вывод

В ходе практической работы были реализованы и исследованы восемь способов поиска максимальной серии одинаковых элементов.

Наиболее эффективным решением по результатам всех трёх экспериментов оказался один проход через итератор.

Динамическое программирование и использование `zip()` также обеспечивают линейную временную сложность, но требуют дополнительной памяти.

Метод разделяй и властвуй решает задачу за линейное время, однако рекурсивные вызовы увеличивают фактическое время выполнения.

Вложенные циклы показали низкую эффективность на данных с длинной серией одинаковых элементов.

Эксперимент показал, что одинаковая асимптотическая сложность не гарантирует одинаковую производительность. Для данной задачи достаточно одного последовательного прохода без создания дополнительных структур данных.
