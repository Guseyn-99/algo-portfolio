**Ограничение памяти:** 256 МБ

## 1. Условие задачи

Вернуть количество различных чисел в списке целых чисел.

**Пример:** `[5, 2, 5, 5, 9, 2] → 3`.

## 2. Методика измерений

Для эксперимента использованы три набора данных:

- 1 000 случайных чисел;
- 100 000 случайных чисел;
- 100 000 случайных чисел от 0 до 99.

Для первых двух наборов выбран диапазон значений от 0 до 1 000 000. Для воспроизводимости эксперимента использовано `random.seed(42)`.

Количество уникальных элементов в наборах:

| Набор | Количество элементов | Количество разных чисел |
|---|---:|---:|
| Малый | 1000 | 1000 |
| Большой | 100000 | 95086 |
| Ограниченный диапазон | 100000 | 100 |

Время измерялось через `time.perf_counter()`. Каждый алгоритм запускался пять раз, после чего вычислялась медиана.

Пиковая дополнительная память измерялась через `tracemalloc`.

Количество проверок определялось с помощью класса `CountedNumber`, учитывающего сравнения значений и вычисления хешей.

Для `bytearray` отдельно учитывались сравнения при поиске минимального и максимального значений, а также проверки ячеек массива.

Копирование входных данных выполнялось до начала замеров.

Обозначение `TIMEOUT` означает превышение двухсекундного лимита ожидания отдельного процесса, включая накладные расходы его запуска.

## 3. Таблица вариантов

Время указано в миллисекундах, пиковая память — в КБ (1024 байта) для n = 100 000.

| Вариант / идея | Время n = 1 000 | Время n = 100 000 | Проверки 1 000 / 100 000 | Худшая сложность | Доп. память | Пик памяти, КБ | Сценарий 1 | Сценарий 2 |
|---|---:|---:|---|---|---|---:|---|---|
| `set()` — преобразование в множество | 0.0470 | 6.8600 | 1000 / 104914 | O(n²) | O(n) | 6144.2578 | Нет — память зависит от числа уникальных элементов | Да — наиболее быстрый вариант по результатам замеров |
| `set` + цикл | 0.0619 | 8.9875 | 1000 / 104914 | O(n²) | O(n) | 6144.2578 | Нет — высокий расход памяти | Нет — медленнее встроенного `set()` |
| `dict` — хранение ключей | 0.0713 | 10.1420 | 1000 / 104914 | O(n²) | O(n) | 7680.0859 | Нет — высокий расход памяти | Нет — избыточное хранение значений |
| `Counter` — подсчёт частот | 0.0995 | 9.8694 | 1000 / 109828 | O(n²) | O(n) | 7684.2256 | Нет — дополнительное хранение частот | Нет — подсчёт частот не требуется |
| `sorted()` — сортировка копии | 0.1643 | 22.9541 | 9644 / 1628870 | O(n log n) | O(n) | 1171.7734 | Нет — создание копии списка требует много памяти | Нет — лишняя сортировка |

| `list` — накопление уникальных чисел | 2.5689 | TIMEOUT | 499500 / TIMEOUT | O(n²) | O(n) | TIMEOUT | Нет — слишком медленный поиск | Нет — большое количество сравнений |

Здесь n — количество элементов, k — размер диапазона значений.

Для решений на основе хеш-таблиц средняя временная сложность составляет O(n). Худшая сложность O(n²) возможна при неблагоприятных хеш-коллизиях.

## 4. Дополнительный эксперимент: числа от 0 до 99

Размер входных данных — 100 000 элементов.

| Вариант | Время, мс | Проверки | Пиковая память, КБ |
|---|---:|---:|---:|
| `set()` | 0.8833 | 199900 | 10.2578 |
| `set` + цикл | 2.6375 | 199900 | 10.2578 |
| `dict` | 2.4291 | 199900 | 6.7109 |
| `Counter` | 3.7507 | 299800 | 11.8584 |
| `sorted()` | 12.6820 | 1155093 | 1168.0625 |
| `sort()` | 12.0930 | 1155093 | 386.7422 |
| `list` | 25.1578 | 5048782 | 0.8906 |
| `bytearray` | 6.0354 | 299998 | 0.2002 |

На наборе с ограниченным диапазоном значений все восемь алгоритмов завершили работу в пределах лимита времени.

Наиболее быстрым оказался `set()`, а наименьшее потребление дополнительной памяти показал `bytearray`.

Количество проверок у `bytearray` не изменилось по сравнению с большим случайным набором, поскольку алгоритм выполняет два прохода для определения границ диапазона и один проход для подсчёта уникальных элементов.

## 6. Выбор решения для заказчиков

### Сценарий 1. Большой вход, память ограничена

**Условия:** n = 10 000 000, дополнительная память не более 8 МБ.

**Условно подходит — `bytearray`.**

Алгоритм расходует дополнительную память в зависимости от диапазона значений, а не непосредственно от количества элементов.

При диапазоне от 0 до 1 000 000 массив занимает примерно 1 МБ. При диапазоне от 0 до 99 измеренная пиковая память составила всего 0.2002 КБ.

Однако диапазон чисел в условиях заказчика не указан. Если разница между минимальным и максимальным значениями слишком велика, алгоритм может превысить ограничение памяти.

Таким образом, ни один из восьми вариантов не гарантирует выполнение всех требований для произвольных целых чисел. Для окончательного выбора необходимо уточнить допустимый диапазон значений.

Замеры при n = 10 000 000 не проводились, поэтому соблюдение двухсекундного ограничения также требует дополнительной проверки.

### Сценарий 2. Малый вход, нужен быстрый ответ

**Условия:** n = 100, значения от 0 до 999.

**Подходит — `set()`.**

Встроенное множество автоматически исключает повторяющиеся элементы. Для получения ответа достаточно определить его длину.

На всех трёх экспериментальных наборах этот вариант показал наименьшее время выполнения.

Алгоритм `bytearray` также подходит для ограниченного диапазона значений и требует мало памяти. Однако при выборе приоритет отдаётся скорости, а не минимальному потреблению памяти.

Отдельные замеры при n = 100 не проводились, поэтому выбор основан на результатах проведённых экспериментов и свойствах алгоритмов.

## 7. Вывод

В ходе практической работы были реализованы и исследованы восемь способов подсчёта различных чисел.

Наиболее быстрым решением по результатам эксперимента оказалось использование встроенного множества `set()`.

Алгоритм на основе обычного списка показал низкую эффективность при большом количестве уникальных элементов из-за последовательного поиска каждого значения.

При ограниченном диапазоне чисел наиболее экономным по дополнительной памяти оказался `bytearray`.

Сортировка требует дополнительных операций, однако позволяет определять уникальные элементы путём сравнения соседних значений.

Эксперимент показал, что при выборе алгоритма важно учитывать размер входных данных, количество уникальных элементов и диапазон их значений.
