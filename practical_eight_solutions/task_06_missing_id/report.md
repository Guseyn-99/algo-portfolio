## 1. Условие задачи

В списке `ids` находятся все числа от 0 до n, кроме одного. Необходимо определить пропущенное число.

**Пример:** `ids = [3, 0, 1], n = 3 → 2`.

## 2. Методика измерений

Для эксперимента использованы три набора данных:

- n = 1 000, список перемешан;
- n = 100 000, список перемешан;
- n = 100 000, пропущено первое число диапазона.

Для воспроизводимости использовалось `random.seed(42)`.

| Набор | Количество элементов | Пропущенное число |
|---|---:|---:|
| Малый | 1000 | 500 |
| Большой | 100000 | 50000 |
| Пропуск в начале | 100000 | 0 |

Время измерялось через `time.perf_counter()`. Каждый алгоритм запускался пять раз, после чего вычислялась медиана.

Пиковая дополнительная память измерялась через `tracemalloc`.

Количество проверок определялось с помощью класса `CountedNumber`, учитывающего сравнения значений и вычисления хешей.

Для `bytearray` и циклической сортировки проверки подсчитывались отдельно. Арифметические, побитовые операции и служебные условия циклов не учитывались.

Копирование входных данных выполнялось до начала замеров.

Обозначение `TIMEOUT` означает превышение двухсекундного лимита ожидания отдельного процесса, включая накладные расходы его запуска.

## 3. Таблица вариантов

Время указано в миллисекундах, пиковая память — в КБ (1024 байта) для n = 100 000.

| Вариант / идея | Время n = 1 000 | Время n = 100 000 | Проверки 1 000 / 100 000 | Худшая сложность | Доп. память | Пик памяти, КБ | Сценарий 1 | Сценарий 2 |
|---|---:|---:|---|---|---|---:|---|---|
| Математическая формула суммы | 0.0100 | 0.7032 | 0 / 0 | O(n) | O(1) | 0.0898 | Да — линейное время и минимальный расход памяти | Да — высокая скорость, исходный список сохраняется |
| XOR — побитовое исключающее ИЛИ | 0.0895 | 9.2498 | 0 / 0 | O(n) | O(1) | 0.2383 | Нет — медленнее выбранного варианта | Нет — большее время выполнения |

| `sorted()` — сортировка копии | 0.1020 | 16.5815 | 9133 / 1579204 | O(n log n) | O(n) | 1171.7812 | Нет — создание копии списка | Нет — лишние затраты на сортировку |

Для решения на основе множества средняя временная сложность составляет O(n). Худшая квадратичная сложность возможна при неблагоприятных хеш-коллизиях.

Пространственная сложность рассматривается в стандартной модели вычислений, где отдельное число занимает постоянное количество машинных слов.

Отсутствие проверок у формулы суммы и XOR не означает постоянную временную сложность. Оба алгоритма обрабатывают все элементы списка.

## 4. Дополнительный эксперимент: пропуск в начале

Размер списка — 100 000 элементов. Пропущенное число — 0. Остальные элементы перемешаны.

| Вариант | Время, мс | Проверки | Пиковая память, КБ |
|---|---:|---:|---:|
| Формула суммы | 0.7796 | 0 | 0.0781 |
| XOR | 8.0746 | 0 | 0.2383 |
| `set` | 4.5747 | 100001 | 6144.2578 |
| `sorted()` | 13.5609 | 1528997 | 1171.7891 |
| `sort()` | 12.0264 | 1528997 | 390.4688 |

При пропуске первого числа наиболее быстрым оказался последовательный поиск.

Алгоритму достаточно проверить отсутствие числа 0 в списке, поэтому в данном случае его временная сложность составляет O(n).

У `bytearray` количество проверок уменьшилось до одной. Однако алгоритм предварительно обрабатывает весь входной список для заполнения массива.

Формула суммы и XOR не зависят от позиции пропущенного числа в диапазоне.

## 6. Выбор решения для заказчиков

### Сценарий 1. Большой вход, память ограничена

**Условия:** n = 10 000 000, дополнительная память не более 8 МБ.

**Подходит — математическая формула суммы.**

Алгоритм вычисляет ожидаемую сумму всех чисел от 0 до n и вычитает фактическую сумму элементов списка.

Формула:

`n * (n + 1) // 2 - sum(ids)`

Временная сложность составляет O(n), дополнительная память — O(1).

При n = 100 000 измеренная пиковая дополнительная память составила 0.0898 КБ, а время выполнения — 0.7032 мс.

Алгоритм не создаёт дополнительных массивов или множеств и не изменяет входные данные.

XOR также соответствует ограничению дополнительной памяти, но уступает формуле суммы по результатам замеров.

Прямой эксперимент при n = 10 000 000 не проводился. Выбор основан на теоретической сложности и полученных результатах. Соблюдение двухсекундного ограничения на полном размере входа требует отдельной проверки.

### Сценарий 2. Малый вход, нужен быстрый ответ

**Условия:** n = 100, ответ нужен быстро, исходный список должен сохраняться.

**Подходит — математическая формула суммы.**

На малом экспериментальном наборе время выполнения составило 0.0100 мс. Это лучший результат среди восьми вариантов на данном наборе.

Алгоритм не изменяет исходный список и не создаёт дополнительных структур данных.

Последовательный поиск может быть быстрее в отдельных случаях, например при пропуске числа 0, однако не обеспечивает стабильную линейную сложность для произвольного пропущенного числа.

Отдельные замеры при n = 100 не проводились. Выбор основан на проведённых экспериментах и свойствах алгоритмов.

## 7. Вывод

В ходе практической работы были реализованы и исследованы восемь способов поиска пропущенного числа.

Математическая формула суммы оказалась наиболее универсальным решением благодаря линейной временной сложности, постоянному расходу дополнительной памяти и сохранению исходного списка.

Побитовая операция XOR позволяет решить задачу без создания дополнительных структур данных.

Циклическая сортировка также работает за линейное время и использует постоянную дополнительную память, но изменяет исходный список.

Последовательный поиск показал высокую зависимость производительности от значения пропущенного числа.

Эксперимент показал, что использование математических свойств входных данных позволяет избежать лишних операций, сортировки и создания дополнительных структур.
