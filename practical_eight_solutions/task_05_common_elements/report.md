## 1. Условие задачи

Вернуть список чисел, присутствующих одновременно в двух списках целых чисел. Повторов в результате быть не должно. Порядок элементов не важен.

**Пример:** `[1, 2, 2, 4], [2, 2, 3] → [2]`.

## 2. Методика измерений

Для эксперимента использованы три набора данных:

- два списка по 1 000 случайных чисел;
- два списка по 100 000 случайных чисел;
- два отсортированных списка по 100 000 чисел.

Случайные числа генерировались в диапазоне от 0 до 1 000 000. Для воспроизводимости использовалось `random.seed(42)`.

Третий набор получен сортировкой второго набора.

| Набор | Размер каждого списка | Количество общих чисел |
|---|---:|---:|
| Малый | 1000 | 0 |
| Большой | 100000 | 9080 |
| Отсортированный | 100000 | 9080 |

Время измерялось через `time.perf_counter()`. Каждый алгоритм запускался пять раз, после чего вычислялась медиана.

Пиковая дополнительная память измерялась через `tracemalloc` с учётом памяти списка результата.

Количество проверок определялось с помощью класса `CountedNumber`, учитывающего сравнения значений и вычисления хешей. Для `bytearray` дополнительно учитывались проверки ячеек массива.

Копирование входных данных выполнялось до начала замеров.

Обозначение `TIMEOUT` означает превышение двухсекундного лимита ожидания отдельного процесса, включая накладные расходы его запуска и проверки результата.

## 3. Таблица вариантов

Время указано в миллисекундах, пиковая память — в КБ (1024 байта) для двух случайных списков по 100 000 элементов.

| Вариант / идея | Время n = 1 000 | Время n = 100 000 | Проверки 1 000 / 100 000 | Худшая сложность | Доп. память | Пик памяти, КБ | Сценарий 1 | Сценарий 2 |
|---|---:|---:|---|---|---|---:|---|---|
| `set` — пересечение множеств | 0.1067 | 18.3111 | 2000 / 218809 | O((n+m)²) | O(n+m) | 10240.4688 | Нет — создание двух множеств требует много памяти | Нет — медленнее выбранного варианта |
| `set` + цикл | 0.0680 | 12.6240 | 2000 / 232156 | O((n+m)²) | O(min(n,m)) | 6144.2578 | Нет — память зависит от количества уникальных элементов | Да — лучшее время по результатам замеров |
| `dict` — поиск по ключам | 0.1010 | 17.0687 | 2000 / 232156 | O((n+m)²) | O(min(n,m)) | 7680.2188 | Нет — высокий расход памяти | Нет — медленнее множества |
| `sorted()` + два указателя | 0.5785 | 64.9399 | 21254 / 3439685 | O(n log n + m log m) | O(n+m) | 1953.0391 | Нет — создание отсортированных копий | Нет — лишние затраты на сортировку |
| `sort()` + два указателя | 0.3986 | 58.9631 | 21254 / 3439685 | O(n log n + m log m) | O(max(n,m)) | 390.4688 | Да, условно — небольшой расход памяти, если разрешено изменение входа | Нет — медленнее выбранного варианта |
| Бинарный поиск | 0.2874 | 48.3482 | 19583 / 3308073 | O(m log m + n log(m+1) + r²) | O(m+r) | 1421.5352 | Нет — копирование списка и хранение множества результата | Нет — дополнительные поиски и сортировка |
| Последовательный поиск | 5.6435 | TIMEOUT | 1000000 / TIMEOUT | O(nm) | O(1) | TIMEOUT | Нет — превышение лимита времени | Нет — большое количество сравнений |
| `bytearray` — таблица значений | 0.4581 | 23.7868 | 8997 / 899994 | O(n+m+k) | O(k) | 1050.5547 | Нет — диапазон значений заказчика неизвестен | Нет — медленнее выбранного варианта |

Обозначения:

- n, m — размеры входных списков;
- k — размер пересечения диапазонов значений;
- r — количество различных общих чисел.

Теоретическая дополнительная память указана без учёта обязательного выходного списка. Экспериментальные замеры учитывают его память.

Для алгоритмов на основе хеш-таблиц средняя временная сложность составляет O(n+m). Худшая квадратичная сложность возможна при неблагоприятных хеш-коллизиях.

В варианте с бинарным поиском дополнительно используется множество для удаления повторов, поэтому его худшая сложность также учитывает возможные хеш-коллизии.

## 6. Выбор решения для заказчиков

### Сценарий 1. Большой вход, память ограничена

**Условия:** в каждом списке 1 000 000 чисел, свободной памяти мало.

**Условно подходит — `sort()` + два указателя.**

Алгоритм сортирует исходные списки на месте и выполняет последовательный поиск общих элементов с помощью двух указателей.

При двух случайных списках по 100 000 элементов измеренная пиковая дополнительная память составила 390.4688 КБ, а на отсортированных данных — 73.9375 КБ.

Непосредственно поиск двумя указателями имеет временную сложность O(n+m) и использует O(1) дополнительной памяти без учёта результата.

Однако сама сортировка может потребовать O(max(n,m)) дополнительной памяти. Также необходимо учитывать размер выходного списка.

Решение подходит при условии, что разрешено изменение входных данных и доступной памяти достаточно для сортировки и хранения результата.

Точный объём свободной памяти заказчик не указал. Прямые замеры на списках по 1 000 000 элементов не проводились, поэтому соблюдение ограничения времени и памяти не гарантируется.

### Сценарий 2. Малый вход, нужен быстрый ответ

**Условия:** в каждом списке 100 чисел, ответ нужен быстро.

**Подходит — `set` с циклом.**

Алгоритм создаёт множество из меньшего списка, затем перебирает второй список. После обнаружения общего числа оно добавляется в результат и удаляется из множества, что предотвращает появление повторов.

На малом экспериментальном наборе время выполнения составило 0.0680 мс. Этот вариант показал наилучшее время на всех трёх наборах данных.

Средняя временная сложность составляет O(n+m).

Отдельные замеры на списках по 100 элементов не проводились. Выбор сделан на основании полученных экспериментальных результатов.

## 7. Вывод

В ходе практической работы были реализованы и исследованы восемь способов поиска общих чисел двух списков.

Наиболее быстрым по результатам экспериментов оказался алгоритм с использованием множества и цикла.

Метод двух указателей позволяет эффективно обрабатывать отсортированные списки и исключать повторное добавление одинаковых элементов.

Сортировка на месте показала небольшой расход дополнительной памяти по сравнению с алгоритмами на основе хеш-таблиц.

Последовательный поиск не уложился в ограничение времени на больших входных данных.

Алгоритм с использованием `bytearray` может быть полезен при ограниченном диапазоне значений.

Эксперимент показал, что при выборе решения необходимо учитывать размеры списков, их отсортированность, количество общих элементов, расход памяти и возможность изменения входных данных.
