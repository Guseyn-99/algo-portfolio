## 1. Условие задачи

Вернуть `True`, если два элемента списка с различными индексами дают сумму `target`. В противном случае вернуть `False`.

**Пример:** `numbers = [2, 7, 11, 15], target = 9 → True`.

## 2. Методика измерений

Для эксперимента использованы три набора данных:

- 1 000 случайных чисел;
- 100 000 случайных чисел;
- 100 000 чисел с подходящей парой в конце.

Целевая сумма равна −10. Случайные числа генерировались в диапазоне от 0 до 1 000 000. В третий набор дополнительно помещены числа −7 и −3, образующие единственную подходящую пару.

Время измерялось через `time.perf_counter()`. Каждый алгоритм запускался пять раз, после чего вычислялась медиана.

Пиковая дополнительная память измерялась через `tracemalloc`.

Количество проверок определялось с помощью класса `CountedNumber`, учитывающего сравнения значений и вычисления хешей. Арифметические операции и служебные условия циклов не учитывались.

Копирование входного списка выполнялось до начала замеров.

Обозначение `TIMEOUT` означает превышение двухсекундного лимита ожидания отдельного процесса, включая накладные расходы его запуска.

## 6. Выбор решения для заказчиков

### Сценарий 1. Большой вход, память ограничена

**Условия:** n = 2 000 000, дополнительная память не более 16 МБ.

**Подходит — `sort()` + два указателя**, если разрешено изменение исходного списка.

Алгоритм сортирует список на месте, после чего выполняет линейный поиск пары с помощью двух указателей.

При n = 100 000 измеренная пиковая дополнительная память составила 390.4531 КБ.

Для CPython на 64-разрядной системе временный буфер сортировки может содержать до n/2 ссылок. При n = 2 000 000 это около 8 МБ памяти под ссылки, что позволяет предварительно считать вариант подходящим по ограничению дополнительной памяти.

Временная сложность составляет O(n log n).

Прямые замеры при n = 2 000 000 не проводились, поэтому соблюдение ограничения в две секунды и фактическое пиковое потребление памяти требуют дополнительной экспериментальной проверки.

### Сценарий 2. Малый вход, нужен быстрый ответ

**Условия:** n = 100, список уже отсортирован.

**Подходит — адаптивный метод двух указателей.**

Алгоритм проверяет отсортированность списка и при необходимости выполняет сортировку. Поскольку входные данные уже упорядочены, сортировка пропускается.

В данном сценарии временная сложность составляет O(n), а дополнительная память — O(1).

Метод использует особенности входных данных и не требует создания множества, словаря или дополнительной копии списка.

Выбор основан на свойствах алгоритма. Отдельный замер на отсортированном списке из 100 элементов не проводился, поэтому преимущество по фактическому времени не подтверждено экспериментально.

## 7. Вывод

В ходе практической работы были реализованы и исследованы восемь способов поиска пары с заданной суммой.

На случайных экспериментальных наборах наиболее быстрым оказался алгоритм с использованием множества `set`.

Два вложенных цикла не уложились в установленное ограничение времени при больших входных данных.

Метод двух указателей позволяет эффективно искать пару в отсортированном списке, используя постоянную дополнительную память непосредственно на этапе поиска.

Сортировка на месте оказалась экономнее по памяти, чем создание отсортированной копии или использование хеш-таблиц.

Эксперимент показал, что при выборе решения необходимо учитывать временную сложность, дополнительную память, состояние входных данных и возможность изменения исходного списка.
